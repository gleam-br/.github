## 🏗️ Structure

Our work is divided between community-driven development and cutting-edge commercial initiatives:

* **[gleam.dev.br](https://gleam.dev.br):** Our **non-profit** arm. An open-source innovation space focused exclusively on Gleam, Erlang/OTP, and JavaScript. This is where the libraries and tools supporting the entire ecosystem are born.
* **[gleam-lang.com.br](https://gleam-lang.com.br):** Our **commercial** operation. Focused on robust enterprise solutions, bridging Gleam and Erlang with the reliability (legacy) of the Java ecosystem and the ubiquity (hype) of JavaScript.
* **[fvideen.com.br](https://fvideen.com.br):** **Freunde Von Ideen**, our software engineering and consulting firm, providing governance and technical expertise across all initiatives.

## 👩‍💻 Why Choose Gleam?

> Ref. https://lozdev.com/why-gleam-deserves-a-spot-in-your-2025-toolkit-beyond-the-syntax/

<details>
  <summary>Click to expand</summary>

### 1. Static Typing and Developer Experience (DX)

Highlighting Gleam's static typing—a distinctive feature that sets it apart from other BEAM languages like Erlang and Elixir.

* **Expressive Types Without Excessive Annotations:** Gleam features an intelligent type inference system. Most of the time, the compiler automatically deduces the types of variables and functions. You only need explicit type declarations at strategic locations (such as public function signatures), yielding cleaner, concise code without sacrificing type safety.
* **The "Safety" of Typing:** Static typing goes well beyond catching syntax or trivial errors; it serves as living, verifiable documentation that clarifies code behavior. The Gleam type system acts as a reliable contract across modules, ensuring correctness before the code even executes.
* **Enhanced Developer Experience (DX):** The Gleam compiler is exceptionally fast, providing clear, human-friendly error messages. This tightens feedback loops, enabling rapid debugging. In addition, static typing powers robust tooling and editor integrations, delivering precise autocomplete and refactoring support.

### 2. The Power of Immutability and Functional Programming

Gleam fully embraces functional programming paradigms, with a central emphasis on **immutability**.

* **Immutable State:** Unlike traditional object-oriented architectures where state can be mutated across execution paths, Gleam guarantees immutability. Once a value is bound, it cannot be modified in place. Transforming data produces a new binding, eliminating common concurrency issues and unintended side effects to deliver predictable, robust behavior.
* **The Pipe Operator (`|>`):** The `|>` pipe operator chains function invocations cleanly and idiomatically. It passes the output of an expression as the first argument to the next function, turning nested calls into an intuitive, left-to-right processing pipeline.

### 3. Concurrency and Fault Tolerance on the BEAM

Gleam runs on the Erlang Virtual Machine (BEAM), an execution platform renowned for mission-critical resilience.

* **More Than "Just" Syntax:** Gleam is not merely an ergonomic language layer over the BEAM; it provides direct access to battle-tested concurrency and fault-tolerant primitives essential for high-availability distributed systems.
* **Lightweight Processes:** Gleam utilizes the BEAM actor model. Instead of relying on operating system threads, the runtime manages lightweight, isolated processes that communicate exclusively via message passing. This avoids shared-memory deadlocks and race conditions.
* **Supervisors and Self-Healing Systems:** Built on OTP (Open Telecom Platform) concepts, supervisors monitor child processes and can restart them automatically upon failure according to defined strategies. This ensures transient errors do not bring down the entire system.

### 4. Interoperability and Ecosystem Flexibility

Gleam bridges multiple execution targets without ecosystem lock-in.

* **BEAM and JavaScript Targets:** Gleam compiles to both Erlang bytecode and modern JavaScript. Developers can leverage the exact same language to write fault-tolerant BEAM backends alongside client-side browser SPAs or Node.js runtimes.
* **Access to Mature Ecosystems:** Rather than rebuilding ecosystems from scratch, Gleam provides foreign function interfaces (FFI) to call existing libraries across Erlang, Elixir, and JavaScript seamlessly.

In summary, Gleam brings together:

* **Static type safety** that elevates developer ergonomics.
* **Functional programming and immutability** for predictable code execution.
* **BEAM reliability** for scalable, fault-tolerant concurrency.
* **Dual-target compilation** across BEAM and JavaScript environments.

Gleam represents a practical addition to modern engineering toolkits, emphasizing simplicity, correctness, and maintainability.

## ⬇️ Installing Gleam

> Ref. [Official Installation Guide](https://gleam.run/getting-started/installing/)

<details>
  <summary>Click to expand</summary>

To set up your machine for Gleam development, you will need the Gleam compiler, Erlang, and optionally editor plugins.

### Precompiled Binaries (Linux, Windows, macOS)

The simplest installation method is downloading prebuilt binaries directly from the [GitHub Releases page](https://github.com/gleam-lang/gleam/releases).

### Building from Source

The compiler is implemented in Rust. To compile from source, ensure you have the [Rust toolchain installed](https://www.rust-lang.org/tools/install).

```shell
# Download the Gleam source repository
cd /tmp
git clone [https://github.com/gleam-lang/gleam.git](https://github.com/gleam-lang/gleam.git) --branch $THE_LATEST_VERSION
cd gleam

# Compile the compiler (this may take a few minutes)
make install

# Verify installation (outputs "gleam $VERSION")
gleam --version

```

### Installing Erlang

When targeting the BEAM, Gleam compiles to Erlang source files, requiring a local Erlang runtime. Some package managers (such as Homebrew) install Erlang as a dependency automatically.

Prebuilt packages across platforms are available from [Erlang Solutions](https://www.erlang-solutions.com/downloads/).

Verify your runtime installation:

```shell
erl -version
Erlang (SMP,ASYNC_THREADS) (BEAM) emulator version 12.1.5

```

### Installing rebar3

When using Erlang dependencies (e.g., HTTP servers or client libraries), you may need the `rebar3` build tool. Follow the [official rebar3 installation instructions](https://rebar3.org/docs/getting-started/).

## 🚀 Case Study: Gleam in Production at Strand

> Ref. https://gleam.run/case-studies/strand/

[Strand](https://www.strand-uk.com/) is a London-based creative agency specializing in marketing copy and content generation for major global tech enterprises, producing hundreds of white papers, case studies, articles, and briefs every year.

### The Challenge

For years, Strand relied on a bespoke internal tool to run its core operations—tracking projects, managing documents, and coordinating team activities. However, financial tracking remained largely manual, using spreadsheets to reconcile billable tasks against purchase orders and invoices.

"Just prior to the pandemic, we decided to build a dedicated financial management application," recalls Ed Kelly, CTO at Strand. "The timing proved crucial. When remote work became necessary, having a unified operational platform kept business continuity seamless."

As the internal tool grew essential to operations, team requirements expanded. Strand's engineering unit wanted to scale the architecture without creating an operational maintenance burden.

"Our prototype rapidly transitioned into mission-critical software," notes Ed Kelly. "With lean technical headcount, reliability was paramount: the system needed to run unattended without constant firefighting. At the same time, we required clean abstractions so engineers could dive back in months later without friction. Our goal was achieving operational stability cost-effectively."

### The Solution

"We run traditional platforms like Python and JavaScript, but we choose tools based on fitness for purpose rather than popularity," says Kelly. "Gleam addressed our requirements directly."

Key adoption factors included static guarantees, low maintenance overhead, clean ergonomics, and native access to mature BEAM infrastructure.

#### Safety and Reliability

"Gleam provides solid compile-time safety," explains Kelly. "Pure Gleam code eliminates entire classes of runtime exceptions. When interfacing with untrusted boundaries, the BEAM runtime provides a second layer of supervision and isolation."

Designed by Ericsson to handle telecommunication networks requiring zero downtime, the BEAM isolates execution into lightweight processes. If an external service integration fails, only the associated process crashes, leaving the core application unharmed.

"Our services interact with several external APIs—syncing exchange rates from official UK portals and updating project boards. Process isolation ensures remote API failures do not degrade overall application availability."

#### Pragmatic Design

"Gleam offers features typically seen in academic functional languages, but packages them with extreme practicality," notes Kelly. "The syntax is clean and focused. Onboarding experienced engineers takes hours rather than weeks, and consistent idioms make team code predictable."

In addition to its standard library, Gleam can invoke libraries from across 40 years of Erlang and Elixir open-source development, allowing teams to deliver without re-implementing core primitives.

#### Developer Experience

"The out-of-the-box tooling is remarkably coherent," Kelly adds. "Formatting, package management, and LSP feedback come integrated. The compiler error messages are clear and diagnostic, speeding up iteration significantly."

"As AI-assisted programming evolves, static verification becomes even more beneficial. Fast compilation and explicit compiler feedback allow automated tooling to validate generated logic immediately, avoiding subtle runtime failures."

#### Incremental Adoption

Strand adopted the language progressively:

"We started small with an isolated currency conversion worker," explains Kelly. "Its stability led us to rewrite other backend modules in Gleam, eventually migrating database persistence layer components. The resulting codebase is substantially easier to maintain."

#### Results

After years in production, Strand's technical leadership considers the decision a clear success:

"We haven't experienced runtime crashes originating from our Gleam layers. When external services experienced issues, the supervisor trees handled recovery transparently," concludes Kelly. "Gleam gives our lean engineering team total operational confidence."
